# Phase 3: Continuous Regression & Non-Linear Upcoding (PyGAM)

## Overview
Traditional healthcare fraud detection often relies on rigid linear thresholds (e.g., flagging providers who bill 2 standard deviations above the mean). However, aggressive upcoding is rarely linear; it operates on a curve, accelerating at specific inflection points before tapering off to avoid triggering automated audits.

Phase 3 transitions from deterministic baselines to **continuous regression modeling**. By utilizing **Generalized Additive Models (PyGAM)** across 802,000 real-world California CMS Medicare claims, this phase maps the hidden, non-linear shape of provider billing behavior. 

## The Methodology: Why PyGAM?
Unlike opaque neural networks ("black-box" AI), PyGAM is a "glass-box" algorithm. It provides the flexibility to model complex, non-linear relationships (using spline functions) while maintaining strict, mathematically interpretable outputs. In a forensic or legal context, an auditor must be able to explain exactly *how* a model arrived at its conclusion. PyGAM generates Partial Dependence Plots (PDPs) that visually and mathematically prove these inflection points.

## Folder Contents
This module contains the core continuous regression script and its visual outputs:

* **`Billing_variance_curve.py`**: The primary Python script. It ingests the processed CMS data, trains the Generalized Additive Model on billing volume versus submitted charges, and generates the variance curves.
* **`pygam_global_variance_curve.png`**: The macro-level plot mapping the baseline behavior across the entire 802k dataset.
* **`pygam_acceleration_threshold_50k.png`**: A granular plot isolating the exact threshold where aggressive billing sharply accelerates beyond the standard clinical baseline.

## Technical Execution
*Note: The raw 802k CMS dataset is `.gitignore`'d at the root level to prevent memory faults and comply with data governance best practices. The script relies on the output generated by the `API_chunked_ingestion.py` ETL pipeline.*

1. **Memory Management:** The script utilizes vectorized Pandas operations to handle the massive dataset without requiring distributed computing (e.g., Spark).
2. **Model Training:** The PyGAM model is fitted using a grid search for optimal smoothing penalties (spline tuning) to prevent overfitting the noise of standard medical billing.
3. **Output:** The script dynamically generates and saves the partial dependence plots into this directory for investigative review.
